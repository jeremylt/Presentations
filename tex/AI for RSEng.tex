\section{Industry Best Practices}
%-------------------------------------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Industry Best Practices}

LLM based coding tools are subject to GIGO

~\\

\includegraphics[height=2cm]{garbage.png} \hspace{10mm} \includegraphics[height=2cm]{garbage.png}\\
Garbage In \hspace{3mm} $\rightarrow$ \hspace{3mm} Garbage Out

~\\

Best practices for input (codebases, planning) and output (process, review)

~\\

'Healthier' codebases more likely to result in higher quality LLM output

~\\

Best practices for human development $\rightarrow$ good codebases for LLM

~\\

High developer skill required for higher quality LLM output

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Caveats}

Quality research on LLM best practices hard to identify

~\\

\begin{itemize}

\item Massive amounts of money in LLM research

~\\

\item Profit motives can complicate research context

~\\

\item Modern research more likely to include positive, definitive wording
(LLM are prone to this as well)

~\\

\item Included impressions from professional discussions, blogs, etc

\end{itemize}

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Code Health}

CodeHealth™ is a quality metric used by CodeScene (paid software suite)

~\\

Corresponds to many 'code smell' concerns

~\\

\begin{itemize}

\item Code cohesion, complexity

~\\

\item Adherence to DRY

~\\

\item Object and method complexity

\end{itemize}

~\\

Higher CodeHealth $\rightarrow$ fewer failing tests after LLM refactoring

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Personal Discussions}

Personal discussions and blogs largely align with CodeScene research

~\\

\includegraphics[height=1.5cm]{discussion.png}

~\\

Skilled developers needed to monitor/fix LLM output quality

~\\

A clear plan and 'definition of done' before development helps greatly

~\\

Overall design and style consistency of particular note

~\\

High developer skill required for higher quality LLM output

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{High Skill Needed}

RSE organizations frequently list skills and training as a weakness

~\\

\tcbox[colback=white,colframe=purple,size=fbox,boxrule=0.8pt,on line]{\includegraphics[height=3.5cm]{derse-concerns.png}}
deRSE list of known community issues

~\\

LLM is not a replacement for professional software skills

~\\

Unfortunately, non-careful LLM usage can also inhibit skill formation

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{De-skilling}

LLM present risk of de-skilling when too much cognition is offloaded

~\\

\includegraphics[height=3.5cm]{deskilling.png}\\
Skill erosion loop (Rinta-Kahila et al.)

~\\


Research software as first class artifacts requires clarity, correctness

~\\

De-skilling presents an important risk to clarity and correctness for RSE

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Summary}

RSEs need \textbf{training in development best practices} to best use LLM

~\\

Skills and training is a \textbf{known weakness} for RSEs

~\\

LLM usage can result in \textbf{de-skilling} or \textbf{inhibit skill formation}

~\\

\textbf{Curating research software like papers} parallels industry best practices

~\\
~\\

\tcbox[colback=white,colframe=purple,size=fbox,boxrule=0.8pt,on line]{Recommendation: Ensure good development skills before using LLM}

\end{center}
\end{frame}

\section{Research Ethics}
%-------------------------------------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Relevant Points}

Three key ethics points:

~\\

\begin{itemize}

\item Research requires \textbf{transparency} in methods, including tools

~\\

\item Software must remain \textbf{legitimate and citable} research

~\\

\item Must \textbf{not plagiarize} work of others, even inadvertently

\end{itemize}

~\\

~\\

\tcbox[colback=white,colframe=purple,size=fbox,boxrule=0.8pt,on line]{See European Code of Conduct for Research Integrity, among others}

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Disclosure}

Disclosure is a natural requirement

~\\

\begin{itemize}

\item Disclosure is at the heart of science

~\\

\item Disclosure improves reproducibility

~\\

\item Successful methods can be re-used

~\\

\item Unsuccessful methods can be avoided

\end{itemize}

~\\

BLUF: If you are uncomfortable stating what you did\\
the software/research is not ready to release and share

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Open Source Policies}

Disclosure aligns with Open Source policies permitting LLM

~\\

\begin{itemize}

\item Many open source project have LLM policies

~\\

\item Disclosure usually required if LLM output permitted

~\\

\item Disclosure can improve code review

\end{itemize}

~\\
~\\

See also Melissa Weber Mendonça's list of open source policies:\\
\tcbox[colback=white,colframe=red,size=fbox,boxrule=0.8pt,on line]{\href{https://github.com/melissawm/open-source-ai-contribution-policies}{https://github.com/melissawm/open-source-ai-contribution-policies}}

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Plagiarism}

Dr Tim Davis prompted Copilot to generate his copyrighted CSparse code\\
without attribution and violating LGPL licensing

~\\

\includegraphics[height=4.2cm]{TimDavisTweet.png}

~\\

Researchers are ultimately responsible for the code they create

~\\

Accidental plagiarism via LLM is still an ethics violation

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Citation Errors}

GPT-4 has fabricated or generated erroneous citations

~\\

Generated citations can have slightly flawed data

~\\

LLM output can omit specific training data related to the prompt

~\\
~\\

RSE should guard against research process inversion:\\research $\rightarrow$ reach conclusions {\color{green} \checkmark}\\conclusions $\rightarrow$ find research to support {\color{red} $\times$}

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Citation Bias}

LLM generated citations reinforce bias in citations

\end{center}
\end{frame}

%------------------------------------------------

\begin{frame}
\begin{center}
\frametitle{Summary}

\textbf{Easy to accidentally plagiarize} with heavy usage

~\\

LLM generated citations can be \textbf{fabricated, flawed, or reinforce bias}

~\\
~\\

\tcbox[colback=white,colframe=purple,size=fbox,boxrule=0.8pt,on line]{\textbf{RSEs are ultimately responsible for our work}, no matter the process}

\end{frame}
